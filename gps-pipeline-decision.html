// 4시간마다 실행 — 가격 긴급 감지 PRICE_WATCH [매 4h: 02:00, 06:00, 10:00, 14:00, 18:00, 22:00] IF 상품_PCI ≥ 130: → 즉시 PRICE-X 트리거 → 다음 일배치 기다리지 않고 즉시 S 부여 → MD에게 긴급 알림 즉시 발송 // 소셜 모니터링 — 바이럴 감지 SURGE_WATCH [실시간 스트림] IF 검색량_MoM ≥ 300% OR 소셜_버즈 감지: → 즉시 SURGE 트리거 → MD 긴급 알림 + 재고 확인 요청 // 외부 크롤링 실패 감시 HEALTH_CHECK [매 1h] IF 크롤링_실패율 > 20%: → 운영팀 알림 (사이트 차단/구조변경 가능성) → 해당 축 데이터 "STALE" 마킹 → 이전값 유지
PART 2. 액션 자동 매칭 의사결정 트리
GPS 점수 → 티어 → 축별 Gap 패턴 분석 → 액션 태스크 자동 배정. 사람이 골라야 하는 수동 개입 불필요.
전체 의사결정 플로우 (위에서 아래로 순차적)
// 상품 1건 입력 → 액션 태스크 출력 function assignAction(product) { // ① 오버라이드 체크 (점수보다 우선) if (product.exists === false) return AUTO_S → 액션: "입점 제안/셀러 컨택" if (product.price.pci >= 130) return PRICE_X → 액션: "가격 즉시 조정" if (product.momentum.mom >= 300 || product.momentum.viral) return SURGE → 액션: "긴급 노출/재고 확보" // ② GPS 점수 산출 → 티어 판정 score = calcGPS(product) tier = score >= 85 ? 'S' : score >= 65 ? 'A' : score >= 40 ? 'B' : 'C' // ③ 축별 Gap 패턴 분석 → 액션 결정 gaps = sortByGap(product.axes) // Gap 내림차순 top1 = gaps[0] // 가장 큰 Gap 축 top2 = gaps[1] // 두 번째 Gap 축 // ④ 매칭 로직 (티어별) return matchAction(tier, top1, top2, product.category) }

액션 태스크 전체 수량 정리 (37 → 22개로 정리)
S등급: 오버라이드 3개(AUTO-S, PRICE-X, SURGE) + top1×top2 조합 4개(가격+딜, 가격+리뷰, 가격+배송, 3축+위기) = 7개
A등급: 단일축 6개 + 복합축 자동생성 = 6개+α
B등급: 단일축 6개 + 승격예방 1개 = 7개
C등급: 모니터링 1개 + 임계감시 1개 = 2개

기존 37개 → 22개 핵심으로 정리. 나머지 15개는 발생 빈도 낮은 변형으로 통합 가능.
